# HTTP/SSE Server & ACP

Reasonix exposes a second frontend over HTTP: the SSE (Server-Sent Events) server streams the controller's event flow to browser clients, while small JSON POST endpoints accept commands. The ACP (Agent Communication Protocol) server provides a standardized agent-to-agent communication interface.

## HTTP/SSE Server

The server (`internal/serve/`) wires a controller to its HTTP surface. One server drives one session; multiple browser tabs share it.

### Routes

| Method | Path | Description |
|--------|------|-------------|
| GET | `/` | Minimal browser client |
| GET | `/events` | SSE event stream |
| GET | `/history` | Message log (ETag-cached) |
| GET | `/context` | Prompt-vs-window gauge (ETag-cached) |
| GET | `/status` | Combined status snapshot |
| GET | `/checkpoints` | Checkpoint list for rewind picker |
| GET | `/branches` | Branch list and tree |
| GET | `/sessions` | Saved session files with titles |
| GET | `/skills` | Discoverable skills |
| POST | `/submit` | Send user input (slash commands + @-refs) |
| POST | `/cancel` | Abort in-flight turn |
| POST | `/approve` | Answer approval request |
| POST | `/plan` | Toggle plan mode |
| POST | `/compact` | Run compaction |
| POST | `/new` | New session |
| POST | `/rewind` | Rewind to checkpoint |
| POST | `/fork` | Fork from checkpoint |
| POST | `/summarize` | Summarize from/upto a turn |
| POST | `/bypass` | Toggle YOLO mode |
| POST | `/answer` | Answer ask_request |
| POST | `/resume` | Load a saved session |
| POST | `/forget` | Delete a saved memory |

### SSE Event Stream

`GET /events` streams the controller's events as `data:` frames:

```
: connected

data: {"kind":"text","text":"Hello"}

data: {"kind":"tool_dispatch","tool":{"id":"call_1","name":"read_file"}}

: ping
```

- Keepalive `: ping` comments are emitted every 15 seconds to prevent reverse proxies from closing idle connections.
- Each event is a single `data:` frame of the JSON wire form.

### CSRF Protection

State-changing endpoints require `Content-Type: application/json`. This forces a CORS preflight that the unauthenticated server never answers, blocking cross-site requests. The same-origin frontend (which always sends JSON) is unaffected.

### CORS

CORS is disabled by default (same-origin policy protects the unauthenticated endpoints). `HandlerWithCORS(origin)` opts in for local development — do NOT use in production.

### Model Switching

`POST /submit` intercepts `/model <ref>` for runtime model switching. The server rebuilds the controller with the new model, carrying over the conversation history. The write lock is held across the rebuild so concurrent requests never read a half-swapped controller.

### Effort Switching

`POST /submit` intercepts `/effort <level>` for reasoning effort switching. This persists the effort level to the user config and rebuilds via `switchModel`.

### Session Titles

Session titles are generated by a lightweight flash model (deepseek-flash with `effort: off`). Titles are cached in a `titleCache` keyed by filename + mtime, so they are only regenerated when the session file changes.

### ETag Caching

`/history` and `/context` support ETag caching — if the client sends `If-None-Match` with the current ETag, the server returns 304 Not Modified with no body, saving bandwidth on reconnects.

### Graceful Shutdown

`RunGraceful()` listens for SIGINT/SIGTERM, drains active connections for up to 10 seconds, then returns.

## ACP (Agent Communication Protocol)

The ACP server (`internal/acp/`) provides a standardized interface for agent-to-agent communication. It implements the Agent Communication Protocol, allowing external systems to interact with the Reasonix agent programmatically.

### Architecture

```
┌──────────────────────────────────────┐
│            ACP Server                 │
│                                      │
│  ┌─────────────┐  ┌──────────────┐   │
│  │  Protocol   │  │  Dispatch    │   │
│  │  Handler    │──►│  Engine      │   │
│  └─────────────┘  └──────┬───────┘   │
│                           │           │
│                    ┌──────▼───────┐   │
│                    │  Service     │   │
│                    │  Layer       │   │
│                    └──────┬───────┘   │
│                           │           │
│                    ┌──────▼───────┐   │
│                    │  Controller  │   │
│                    └──────────────┘   │
└──────────────────────────────────────┘
```

### Key Components

- **`protocol.go`** — Defines the ACP message types and wire format.
- **`dispatch.go`** — Routes incoming ACP messages to the appropriate handler.
- **`service.go`** — Implements the ACP service layer, translating ACP operations to controller commands.
- **`server.go`** — The HTTP server that accepts ACP connections.

### ACP Endpoints

The ACP server exposes endpoints for:
- Creating and managing agent sessions
- Sending messages and receiving responses
- Subscribing to agent events
- Querying agent capabilities and status

### Protocol

The ACP protocol is JSON-based, with messages consisting of:
- A message type (request/response/notification)
- A method name
- Parameters
- An optional correlation ID

### Dispatch

The dispatch engine routes incoming messages by method name, validates parameters, and invokes the corresponding service method. Partial messages (streaming responses) are supported for long-running operations.

### Service Layer

The service layer bridges ACP operations to the `control.Controller`:
- `SendMessage` → `controller.Submit()`
- `CancelOperation` → `controller.Cancel()`
- `ApproveAction` → `controller.Approve()`
- `GetStatus` → `controller.Running()` + context stats
- `ListCapabilities` → tools + skills

## Broadcaster

The `Broadcaster` (`internal/serve/broadcaster.go`) is an event sink that fans out events to multiple subscribers (SSE clients, ACP connections):

```go
type Broadcaster struct {
    mu    sync.RWMutex
    subs  map[int64]chan []byte
    next  int64
}
```

- `Subscribe()` returns a channel and an unsubscribe function.
- `Emit()` serializes the event to JSON and sends it to all subscribers.
- Non-blocking sends — slow subscribers are dropped.
